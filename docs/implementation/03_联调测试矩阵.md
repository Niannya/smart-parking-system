# 智能停车场管理系统：联调与验收测试矩阵

> 2026-11-16；执行清单，不是测试结果。实际证据与签名填[里程碑验收记录](../milestones/停车场项目_里程碑验收记录.md)。逐项运行后才能把状态改成通过。

## 1. 可重复的环境与记录格式

1. 三人从同一 `dev` 提交开始，记录 `git rev-parse --short HEAD`。在**空** PostgreSQL 数据库依次执行 `database/01_schema.sql`、`database/02_seed_data.sql`；不要在已有生产/个人数据上重置。该演示脚本提供两个停车场、每场两个区域/20 个车位，以及虚构 ADMIN/OWNER 账号。测试账号只用于本地演示；更换密码写在本机环境，不提交真实口令。
2. 后端 Java 21、`backend\mvnw.cmd -version`；数据库连接从本机环境变量配置。前端在 `frontend` 执行 `npm ci`、`npm run dev`。运行自动化测试及构建时记录退出码、最后关键输出；手工测试记录日期、操作者、账号角色、场 ID、请求/响应或截图。
3. 每个测试使用独立的车牌或事务回滚/专用测试库；不要依赖执行顺序后遗留的状态。时间边界、计费函数测试用固定时钟，不等待真实 26 小时。涉及锁/并发的用真实 PostgreSQL，不把 H2/Mock 结果当数据库并发证据。
4. `git status --short` 与 `git diff --check` 无意外文件；`backend/target`、`frontend/node_modules` 不进入 Git。后端 `.\mvnw.cmd test` / `package`，前端 `npm run build` 都应退出 0。

## 3. 给 AI 的测试实现要求

- 成员 1：认证用 MockMvc + 真实安全过滤链；停车场和统计用 PostgreSQL 集成测试。明确通过 `/api/auth/csrf` 获取 token，覆盖无 token 的拒绝。
- 成员 2：区域/车位/车辆 CRUD 可用服务/接口测试；入场必须用真实 PostgreSQL 的约束与并发测试。并发用两个独立事务及启动门闩，让两个请求争同一车位。
- 成员 3：`FeeCalculator` 做纯函数单元测试，quote/支付/异常路径做服务与 PostgreSQL 事务测试；主动注入中间步骤异常验证三表回滚。
- 前端由各成员对自己页面完成手工联调和截图，成员 1 负责整体路由登录态；不可只用前端隐藏按钮验证权限。
