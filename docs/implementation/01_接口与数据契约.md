# 智能停车场管理系统：接口与数据契约

> 2026-11-16；本文件是[工程总契约](00_工程实施规格.md)的接口附录。**目标规格，不是现有接口清单。** 三人确认后冻结；改变字段、路由或错误码须先改本文件并通知受影响成员。数据库真实列和约束以[建表脚本](../../database/01_schema.sql)为准。

## 1. 所有接口共同规则

- 后端前缀 `/api`；所有路径均由后端校验角色。标注 `ADMIN` / `OWNER` 的接口必须登录；默认不允许匿名。`GET /api/auth/csrf`、注册、登录为例外。
- 响应固定 `{"code":0,"message":"操作成功","data":...}`。成功 HTTP 200；参数 400、未登录 401、无权 403、未找到 404、业务冲突 409、未知错误 500。失败 `data:null`；列表空值 `[]`。禁止把 SQL 异常原文送给前端。
- 所有 ID 为数据库 `BIGINT`，JSON 数字；金额为两位小数的十进制 JSON 数字，后端用 `BigDecimal`，前端只显示、不用 JavaScript 浮点数重新计费。时间为含偏移的 ISO 8601 字符串，例如 `2026-11-16T10:30:00+08:00`。请求中的 `from`/`to` 也须带偏移；范围为 `[from,to)`。日期为 `YYYY-MM-DD`，以 `Asia/Shanghai` 划日。
- 请求未知字段直接拒绝（400），尤其不能接收 `role`、`ownerUserId`、`entryAdminId`、`exitAdminId`、`handledBy`、`feeRuleId`、`entryTime`、`exitTime`、`status:PARKING/OCCUPIED` 这类服务端控制值。路径 ID 必须为正整数；必填字符串 trim 后不能为空；编号和车牌 trim 后转大写。长度以 SQL 列为上限。
- 车牌格式使用课程项目约定的普通小型车基础校验：`^[京津沪渝冀豫云辽黑湘皖鲁新苏浙赣鄂桂甘晋蒙陕吉闽贵粤青藏川宁琼][A-Z][A-HJ-NP-Z0-9]{5,6}$`。这是输入校验，不声称覆盖全部真实车牌种类。特殊车牌不在本课设范围。
- POST/PUT/PATCH 带 JSON `Content-Type: application/json` 和会话 Cookie、`X-XSRF-TOKEN`；前端统一 `src/api/http.js` 处理。登录成功或退出后重新获取 CSRF token。无 token 的写操作应为 403。
- 集合接口不分页，按本文件规定排序；字段省略代表不过滤，空字符串过滤值报 400。后续若三人同意加分页须形成一次契约修订。

| 方法与路径 | 请求 | 返回 |

`FeeRule={"id":1,"parkingLotId":1,"ruleName":"日常规则","freeMinutes":30,"billingUnitMinutes":60,"unitPrice":5.00,"maxFeePer24h":50.00,"isActive":true,"effectiveFrom":"…","effectiveTo":null,"createdBy":1,"createdAt":"…"}`。整数非负、单价/封顶费非负，计费单位正数。创建新规则时同一事务锁**启用**停车场→旧规则 `is_active=false,effective_to=now`→插新规则 `is_active=true,effective_from=now`。历史规则不可改删，停车记录保留原 `feeRuleId`；无 PUT/DELETE。

### 费用纯函数（成员 3，内部契约）

`calculate(entryTime, exitTime, feeRule) -> {durationMinutes, amountDue}`。`exitTime>=entryTime`，时长为两时刻间秒数**向上取整至分钟**；不满或等于 `freeMinutes` 为 0。超过免费时，先从总分钟扣免费分钟，对余量按连续的 1440 分钟周期分段；各段 `min(ceil(段分钟 / billingUnitMinutes) * unitPrice, maxFeePer24h)` 后相加。金额保持两位小数。例：30 免费、60 单位、5 元、24h 50 封顶：30 分钟 0；31 分钟 5；26 小时 60。单元测试以固定时钟验证，不用 `Thread.sleep`。

## 5. 入场、离场与异常处理（成员 2 / 3）

### 入场（成员 2，ADMIN）

`POST /api/parking-entries`：请求 `{"lotId":1,"licensePlate":"京A12345"}`；返回：

`{"id":101,"recordNo":"R1234567890abcdef1234567890abcde","lotId":1,"licensePlate":"京A12345","spaceId":11,"areaCode":"A","spaceCode":"001","feeRuleId":3,"entryTime":"2026-11-16T10:30:00+08:00","status":"PARKING"}`。

校验顺序：规范化车牌/校验格式→当前会话 ADMIN→事务中锁启用停车场→确认全局无同牌 `PARKING`→取该场活动规则→仅在该场启用区域选 FREE 车位，按 `areaCode,spaceCode,id` 排序→条件占用→插入记录。`recordNo` 由服务器生成不超过 32 字符且唯一；约定格式为 `R` + UUID 去连字符后的前 31 位（共 32 字符），若唯一索引极罕见冲突则在事务内重试生成，不将碰撞呈现为重复车牌；支付编号同理为 `P` + 31 位。`entryAdminId` 从会话。已启用绑定车辆则存 `vehicleId`，否则作为临时车存 null。任一步失败回滚。不同场的同牌也不允许同时在场，因为 SQL 唯一索引是全局的。

### 在场查询、费用预览与正常离场（成员 3，ADMIN）

| 方法与路径 | 请求 | 返回 |
| --- | --- | --- |
| GET `/api/parking-exits/active?licensePlate=京A12345` 或 `?recordNo=R...` | 二者恰填一个；车牌须规范化 | `ActiveRecord`，无则 404/4501 |
| GET `/api/parking-exits/{recordId}/quote` | 无 | `Quote`，只接受 PARKING |
| POST `/api/parking-exits/{recordId}` | `{"paymentMethod":"CASH","amountPaid":5.00,"remark":null}` | `ExitResult` |
| POST `/api/parking-exits/{recordId}/abnormal` | `{"reason":"人工核实后异常离场"}` | `ExitResult`，`paymentNo:null` |

`ActiveRecord={"id":101,"recordNo":"…","lotId":1,"licensePlate":"京A12345","spaceId":11,"areaCode":"A","spaceCode":"001","entryTime":"…","status":"PARKING"}`。

`Quote={"recordId":101,"entryTime":"…","quotedExitTime":"…","durationMinutes":61,"amountDue":5.00,"feeRuleId":3}`。预览只供显示，不锁定最终金额；确认离场重新按服务器当时 `exitTime` 和记录已绑定的 `feeRuleId` 计算。不要接受客户端发送的 `amountDue`、`exitTime`、`feeRuleId`。

`ExitResult={"recordId":101,"paymentNo":"P1234567890abcdef1234567890abcde","exitTime":"…","durationMinutes":61,"amountDue":5.00,"amountPaid":5.00,"status":"COMPLETED","spaceStatus":"FREE"}`。支付方法 `CASH`、`ELECTRONIC`、`FREE_RELEASE`。前两者 `amountPaid` 必须等于服务端应收额（金额 0 也允许）；`FREE_RELEASE` 强制 `amountPaid=0` 且 `remark` 非空，保留原 `amountDue` 便于核对减免。这里是**模拟确认收款**，不接真实支付渠道。免费放行指减免操作，不等同于规则计算结果为 0。

正常离场一事务：锁在场记录→读取其规则/车位→计算→校验支付→插 `payment_record`→更新记录 `COMPLETED`、写 `exitTime/exitAdminId`→条件释放 `OCCUPIED→FREE`；任何失败回滚。一个停车记录只能有一个 payment，重复 POST 为 409/4502，不返回第二次成功。`paymentNo` 服务端唯一生成。

异常离场是需求中保留的人工处置通道：只有 ADMIN 可调用，原因必填；锁记录并在同一事务设置 `ABNORMAL`、`abnormalReason`、`exitTime`、`exitAdminId` 并释放车位，**不生成支付记录**；默认不计收入。页面需二次确认并展示原因；重复操作 409/4502。是否补收需全组另行定契约，不能私自将 ABNORMAL 当 COMPLETED。

### 停车记录（成员 3）

| GET `/api/parking-records?lotId=1&licensePlate=京A12345&status=COMPLETED&spaceId=11&from=…&to=…` | ADMIN | 过滤项均可省；`from/to` 应同时提供；按 `entryTime DESC,id DESC` | `Record[]` |
| GET `/api/parking-records/{id}` | ADMIN | 无 | `Record` |

`Record={"id":101,"recordNo":"…","lotId":1,"lotName":"中心停车场","vehicleId":5,"licensePlate":"京A12345","spaceId":11,"areaCode":"A","spaceCode":"001","feeRuleId":3,"entryTime":"…","exitTime":"…或null","durationMinutes":61,"estimatedAmountDue":null,"status":"COMPLETED","paymentStatus":"PAID","abnormalReason":null,"payment":{"paymentNo":"…","amountDue":5.00,"amountPaid":5.00,"paymentMethod":"CASH","paymentTime":"…"}}`。`durationMinutes` 用同一向上取整规则；PARKING 以查询时刻计算并提供 `estimatedAmountDue`（按绑定规则预估）、`paymentStatus:"UNPAID"`、`payment:null`；COMPLETED 的 `estimatedAmountDue=null`，正常收款 `paymentStatus:"PAID"`，FREE_RELEASE 为 `"WAIVED"`；ABNORMAL 为 `"ABNORMAL"`、`payment:null`。管理员和车主使用同一可见 DTO，但不返回内部 admin IDs。车主列表与详情必须 `JOIN vehicle ON record.vehicle_id=vehicle.id AND vehicle.owner_user_id=当前会话用户`，不能仅凭车牌快照，更不能接受客户端提供的 owner ID。历史临时车记录不会因后来绑定同车牌自动变成本人可见。

### 管理首页（成员 1，ADMIN）

`GET /api/dashboard/summary?lotId=1&date=2026-11-16`，`lotId` 可省表示全场，`date` 可省表示今天（上海时区）。返回：

`{"lotId":1,"date":"2026-11-16","totalSpaces":20,"freeSpaces":17,"occupiedSpaces":2,"disabledSpaces":1,"occupancyRate":10.53,"entryCount":6,"exitCount":4,"totalRevenue":20.00}`。

车位数是当前状态快照，停用车位不进入占用率分母：`occupied/(free+occupied)*100`，四舍五入两位；分母 0 时为 0。`entryCount` 按 `entry_time`、`exitCount` 按 `exit_time`、`totalRevenue` 按 `payment_time` 落在所选本地日期区间计，收入求和 `amount_paid`；ABNORMAL 计离场数、不计收入。`lotId` 省略时 `data.lotId=null`，先按场过滤再聚合，不能把所有场的规则或记录混在单场视图。

`GET /api/dashboard/revenue?lotId=1&from=2026-11-01T00:00:00%2B08:00&to=2026-12-01T00:00:00%2B08:00`：`from/to` 必填且 `from<to`，`lotId` 可省（URL 中的加号须编码为 `%2B`）。返回 `{"lotId":1,"from":"…","to":"…","paymentCount":8,"totalRevenue":60.00}`。只统计 `payment_time∈[from,to)` 的 `payment_record.amount_paid`，按关联停车记录的 lotId 过滤；FREE_RELEASE 的 0 元支付计入 paymentCount 但不增收入，ABNORMAL 无支付不计。这样覆盖需求中的“指定日期或时间范围内的停车收入”。

## 8. 最小可复制的联调请求

以下示例省略登录时的 Cookie/token 获取细节；实际写请求必须带会话和 CSRF。先使用 `database/02_seed_data.sql` 的虚构演示账号。按顺序检查：管理员登录 → `GET /api/parking-lots/options` 返回两场 → `GET /api/fee-rules/active?lotId=1` → `POST /api/parking-entries` → `GET /api/parking-exits/{id}/quote` → `POST /api/parking-exits/{id}` → `GET /api/parking-records/{id}` → `GET /api/dashboard/summary?lotId=1`。再用 OWNER 登录，`GET /api/owner/parking-records` 可见绑定车辆记录；将别人的 record ID 放到详情路径必须 403。
