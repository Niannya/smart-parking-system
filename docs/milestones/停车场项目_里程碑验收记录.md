> 本文件是**待填写的记录表，不是已通过的证明**。`结论`只填“通过”或“不通过”；未执行留空。每条证据写可打开的 PR、测试报告、截图、日志或复现步骤，不能只写“已测试”。

## 使用方法

1. 任务作者运行自测并填写证据；非作者复核后填写结论、姓名和日期。自动化测试填命令、退出码与关键输出；手工操作填步骤和截图/录屏路径。
2. 不通过时在[缺口表](#缺口与复验)登记负责人、修复 PR 和复验结果。修改依赖分支或共享契约后，受影响的旧测试结果应重跑。
3. 一个里程碑内所有必做项均“通过”，且对应代码合入 `dev` 后完成烟测，才在[闸口总表](#闸口总表)签收。已合并 PR 不自动等于通过。
4. 分工表中的任务 ID 与本文件验收 ID 一一对应或被本文件明确组合；第 12 节[需求验收](../智能停车场管理系统_需求分析.md)仍是最终口径。

## 签收说明

- 任务状态由任务负责人维护，结论由非作者填写；一人同时是作者与组长时，仍须由另一名组员复核。
- 失败用例的预期是“正确拒绝且数据不变”，不是要求所有 HTTP 请求都成功。
- 需要截图/录屏的手工证据由执行该用例的组员留存；本表只填写实际存在的证据路径，不预填不存在的产物。
