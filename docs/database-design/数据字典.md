# 智能停车场管理系统数据字典

> 项目：`smart-parking-system`  
> 设计分支：`docs/database-design`  
> 数据库：PostgreSQL  
> 编写日期：2026-10-27  
> 配套文档：[ER 图](ER图.md)

## 1. 设计约定

### 1.1 命名规则

- 表名、字段名、约束名和索引名统一使用小写蛇形命名法 `snake_case`。
- 表名使用单数形式，例如 `parking_space`，不使用 `parking_spaces`。
- 主键统一命名为 `id`。
- 外键使用“实体名 + `_id`”，例如 `area_id`。
- 时间字段使用 `_time` 或 `_at` 后缀。
- 布尔字段使用 `is_` 前缀。
- 状态和业务编号在数据库中保存英文大写值，页面负责显示中文。

### 1.2 通用数据类型

| PostgreSQL 类型 | Java 类型建议 | 用途 |
| --- | --- | --- |
| `BIGINT` | `Long` | 主键和外键 |
| `VARCHAR(n)` | `String` | 编号、名称、状态、说明 |
| `INTEGER` | `Integer` | 分钟数等整数 |
| `NUMERIC(10,2)` | `BigDecimal` | 金额，禁止使用 `double` 计算费用 |
| `BOOLEAN` | `Boolean` | 是否当前生效等开关 |
| `TIMESTAMPTZ` | `OffsetDateTime` 或 `Instant` | 入场、离场、支付和审计时间 |

### 1.3 通用规则

- 主键采用 `BIGINT GENERATED BY DEFAULT AS IDENTITY`。
- 金额统一使用 `NUMERIC(10,2)`，单位为人民币元。
- 时间统一使用 `TIMESTAMPTZ`，避免不同电脑时区造成歧义。
- 项目展示时区为 `Asia/Shanghai`。
- `created_at` 默认当前时间。
- `updated_at` 新增时默认当前时间，修改数据时由后端更新。
- 业务历史表不执行物理删除。
- MyBatis 已启用下划线转驼峰，数据库 `parking_space_id` 可映射为 Java `parkingSpaceId`。

| 表名 | 中文名称 | 主要用途 |

## 3. `admin_user` 管理员表

### 3.1 用途

保存管理员登录信息。系统不区分管理员、操作员等不同角色，因此不设置角色字段。可以存在多个拥有相同权限的管理员账号。

### 3.2 字段

| 字段名 | 类型 | 可空 | 默认值 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | `BIGINT` | 否 | 自增 | 主键 | 管理员内部编号 |
| `username` | `VARCHAR(50)` | 否 | 无 | 唯一；去除首尾空格后不能为空 | 登录用户名，建议统一转为小写保存 |
| `password_hash` | `VARCHAR(255)` | 否 | 无 | 不能为空 | BCrypt 等安全算法生成的密码摘要，禁止保存明文密码 |
| `display_name` | `VARCHAR(50)` | 否 | 无 | 去除首尾空格后不能为空 | 页面显示姓名 |
| `status` | `VARCHAR(20)` | 否 | `ACTIVE` | `ACTIVE`、`DISABLED` | 账号状态 |
| `created_at` | `TIMESTAMPTZ` | 否 | 当前时间 | 无 | 创建时间 |
| `updated_at` | `TIMESTAMPTZ` | 否 | 当前时间 | 无 | 最后修改时间 |

### 3.3 业务规则

- 用户名全局唯一。
- 只有 `ACTIVE` 状态的管理员可以登录。
- 有业务记录的管理员不能物理删除，只能改为 `DISABLED`。
- 数据库初始化脚本中的默认管理员密码也必须以密码摘要保存。

## 4. `parking_area` 停车区域表

### 4.1 用途

保存停车场内的区域，例如 A 区、B 区。系统只管理一个停车场，因此区域不需要关联停车场表。

### 4.2 字段

| 字段名 | 类型 | 可空 | 默认值 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | `BIGINT` | 否 | 自增 | 主键 | 区域内部编号 |
| `area_code` | `VARCHAR(20)` | 否 | 无 | 唯一；不能为空 | 区域业务编号，例如 `A`、`B` |
| `area_name` | `VARCHAR(50)` | 否 | 无 | 不能为空 | 区域名称，例如“A 区” |
| `description` | `VARCHAR(255)` | 是 | `NULL` | 无 | 区域说明 |
| `status` | `VARCHAR(20)` | 否 | `ACTIVE` | `ACTIVE`、`DISABLED` | 区域状态 |
| `created_at` | `TIMESTAMPTZ` | 否 | 当前时间 | 无 | 创建时间 |
| `updated_at` | `TIMESTAMPTZ` | 否 | 当前时间 | 无 | 最后修改时间 |

### 4.3 业务规则

- `area_code` 全局唯一，建议转换为大写保存。
- 区域下存在停车位时不允许物理删除。
- `DISABLED` 区域中的车位不参与自动分配。
- 停用区域前应确保该区域没有正在停车的车辆。

## 5. `parking_space` 停车位表

### 5.1 用途

保存停车位所属区域、车位编号和实时状态。本课程设计不区分车位类型。

### 5.2 字段

| 字段名 | 类型 | 可空 | 默认值 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | `BIGINT` | 否 | 自增 | 主键 | 停车位内部编号 |
| `area_id` | `BIGINT` | 否 | 无 | 外键 → `parking_area.id` | 所属区域 |
| `space_code` | `VARCHAR(20)` | 否 | 无 | 与 `area_id` 组成唯一约束 | 区域内车位编号，例如 `001` |
| `status` | `VARCHAR(20)` | 否 | `FREE` | `FREE`、`OCCUPIED`、`DISABLED` | 当前状态 |
| `description` | `VARCHAR(255)` | 是 | `NULL` | 无 | 维修情况等备注 |
| `created_at` | `TIMESTAMPTZ` | 否 | 当前时间 | 无 | 创建时间 |
| `updated_at` | `TIMESTAMPTZ` | 否 | 当前时间 | 无 | 最后修改时间 |

### 5.3 唯一约束

```text
UNIQUE (area_id, space_code)
```

不同区域可以存在相同局部编号，例如 A 区 `001` 和 B 区 `001`；同一区域内不能重复。

### 5.4 业务规则

- 只有启用区域中的 `FREE` 车位可以分配。
- 车辆入场成功时由 `FREE` 改为 `OCCUPIED`。
- 车辆正常离场或异常放行完成时由 `OCCUPIED` 改为 `FREE`。
- 只有 `FREE` 车位可以改为 `DISABLED`。
- 有历史停车记录的车位不能物理删除。
- 页面完整编号可以由 `area_code` 和 `space_code` 组合显示，例如 `A-001`。

## 6. `fee_rule` 收费规则表

### 6.1 用途

保存停车计费参数。修改收费标准时新增一条规则，不直接覆盖已经被停车记录引用的旧规则。

### 6.2 字段

| 字段名 | 类型 | 可空 | 默认值 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | `BIGINT` | 否 | 自增 | 主键 | 收费规则内部编号 |
| `rule_name` | `VARCHAR(50)` | 否 | 无 | 不能为空 | 规则名称，例如“默认收费规则” |
| `free_minutes` | `INTEGER` | 否 | `30` | 大于等于 0 | 整次停车享受一次的免费分钟数 |
| `billing_unit_minutes` | `INTEGER` | 否 | `60` | 大于 0 | 一个计费单位的分钟数 |
| `unit_price` | `NUMERIC(10,2)` | 否 | `5.00` | 大于等于 0 | 每个计费单位的价格 |
| `max_fee_per_24h` | `NUMERIC(10,2)` | 否 | `50.00` | 大于等于 0 | 每连续 24 小时周期的最高费用 |
| `is_active` | `BOOLEAN` | 否 | `FALSE` | 同一时刻最多一条为真 | 是否为当前入场车辆使用的规则 |
| `effective_from` | `TIMESTAMPTZ` | 否 | 当前时间 | 无 | 生效时间 |
| `effective_to` | `TIMESTAMPTZ` | 是 | `NULL` | 不早于 `effective_from` | 失效时间，当前有效规则为空 |
| `created_by` | `BIGINT` | 否 | 无 | 外键 → `admin_user.id` | 创建管理员 |
| `created_at` | `TIMESTAMPTZ` | 否 | 当前时间 | 无 | 创建时间 |

### 6.3 业务规则

- 同一时刻只能有一条 `is_active = TRUE` 的收费规则。
- 启用新规则时，在同一事务中停用旧规则并填写其 `effective_to`。
- 车辆入场时把当前规则的 `id` 写入 `parking_record.fee_rule_id`。
- 已经被停车记录引用的规则不能物理删除，也不能修改计费参数。
- 默认规则为：30 分钟免费、每 60 分钟 5 元、每连续 24 小时封顶 50 元。

### 6.4 计费公式

设总停车分钟数为 `total_minutes`：

1. 若 `total_minutes <= free_minutes`，应收金额为 0。
2. 否则 `billable_minutes = total_minutes - free_minutes`。
3. 将 `billable_minutes` 按连续 24 小时，即 1440 分钟拆分为多个周期。
4. 每个周期的费用为：

```text
min(
  ceil(周期内计费分钟数 / billing_unit_minutes) × unit_price,
  max_fee_per_24h
)
```

5. 所有周期费用之和为应收金额。

金额运算必须使用 `BigDecimal`，不能使用 `double`。

## 7. `parking_record` 停车记录表

### 7.1 用途

保存普通小型汽车从入场到离场的一次完整停车过程。车牌号码作为停车事件属性直接保存在本表中。

### 7.2 字段

| 字段名 | 类型 | 可空 | 默认值 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | `BIGINT` | 否 | 自增 | 主键 | 停车记录内部编号 |
| `record_no` | `VARCHAR(32)` | 否 | 无 | 唯一 | 对外显示的停车记录编号 |
| `license_plate` | `VARCHAR(15)` | 否 | 无 | 不能为空 | 规范化后的车牌号码 |
| `parking_space_id` | `BIGINT` | 否 | 无 | 外键 → `parking_space.id` | 本次停车使用的车位 |
| `fee_rule_id` | `BIGINT` | 否 | 无 | 外键 → `fee_rule.id` | 入场时绑定的收费规则 |
| `entry_admin_id` | `BIGINT` | 否 | 无 | 外键 → `admin_user.id` | 办理入场的管理员 |
| `exit_admin_id` | `BIGINT` | 是 | `NULL` | 外键 → `admin_user.id` | 办理离场或异常结束的管理员 |
| `entry_time` | `TIMESTAMPTZ` | 否 | 当前时间 | 无 | 入场时间 |
| `exit_time` | `TIMESTAMPTZ` | 是 | `NULL` | 不早于 `entry_time` | 离场或异常结束时间 |
| `status` | `VARCHAR(20)` | 否 | `PARKING` | `PARKING`、`COMPLETED`、`ABNORMAL` | 停车记录状态 |
| `abnormal_reason` | `VARCHAR(500)` | 是 | `NULL` | 异常状态时必填 | 异常结束原因 |
| `created_at` | `TIMESTAMPTZ` | 否 | 当前时间 | 无 | 创建时间 |
| `updated_at` | `TIMESTAMPTZ` | 否 | 当前时间 | 无 | 最后修改时间 |

### 7.3 编号规则

`record_no` 由后端生成，推荐格式：

```text
PR + yyyyMMddHHmmss + 4 位随机字符
```

例如：`PR20261027143015A7K2`。数据库仍需设置唯一约束，防止极低概率的编号重复。

### 7.4 车牌规范

- 去除首尾和中间多余空格。
- 英文字母统一转换为大写。
- 按中国大陆普通小型汽车车牌格式进行基础校验。
- 数据库保存规范化后的值，查询前也执行相同规范化。

### 7.5 状态与字段组合规则

| 状态 | `exit_time` | `exit_admin_id` | `abnormal_reason` |
| --- | --- | --- | --- |
| `PARKING` | 必须为空 | 必须为空 | 必须为空 |
| `COMPLETED` | 必须非空 | 必须非空 | 可以为空 |
| `ABNORMAL` | 必须非空 | 必须非空 | 必须非空 |

### 7.6 并发与唯一性

需要使用 PostgreSQL 部分唯一索引实现：

- `status = 'PARKING'` 时，`license_plate` 唯一。
- `status = 'PARKING'` 时，`parking_space_id` 唯一。

这两项约束可以阻止并发请求导致同一车辆重复入场或同一车位被重复分配。

## 8. `payment_record` 收费记录表

### 8.1 用途

保存停车结算结果。停车中的记录不创建收费记录；完成支付或免费放行时创建一条收费记录。

### 8.2 字段

| 字段名 | 类型 | 可空 | 默认值 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `id` | `BIGINT` | 否 | 自增 | 主键 | 收费记录内部编号 |
| `payment_no` | `VARCHAR(32)` | 否 | 无 | 唯一 | 对外显示的收费编号 |
| `parking_record_id` | `BIGINT` | 否 | 无 | 外键 → `parking_record.id`；唯一 | 对应停车记录 |
| `amount_due` | `NUMERIC(10,2)` | 否 | 无 | 大于等于 0 | 按收费规则计算的应收金额 |
| `amount_paid` | `NUMERIC(10,2)` | 否 | 无 | 大于等于 0 | 实际收取金额 |
| `payment_method` | `VARCHAR(20)` | 否 | 无 | `CASH`、`ELECTRONIC`、`FREE_RELEASE` | 支付方式 |
| `payment_time` | `TIMESTAMPTZ` | 否 | 当前时间 | 无 | 支付确认或免费放行时间 |
| `handled_by` | `BIGINT` | 否 | 无 | 外键 → `admin_user.id` | 办理管理员 |
| `remark` | `VARCHAR(500)` | 是 | `NULL` | 免费放行时必填 | 收费备注或免费放行原因 |
| `created_at` | `TIMESTAMPTZ` | 否 | 当前时间 | 无 | 创建时间 |

### 8.3 编号规则

`payment_no` 由后端生成，推荐格式：

```text
PAY + yyyyMMddHHmmss + 4 位随机字符
```

例如：`PAY20261027170020B9M4`。

### 8.4 业务规则

- `parking_record_id` 唯一，保证一条停车记录最多结算一次。
- `CASH` 和 `ELECTRONIC` 表示模拟支付，不接入真实支付平台。
- `FREE_RELEASE` 时 `amount_paid` 必须为 0，且 `remark` 必须填写原因。
- 正常支付时允许记录应收金额和实收金额，但两者不允许为负数。
- 收费记录创建后不提供修改和删除功能；确需更正时应保留审计说明，不直接覆盖历史。

## 11. 索引建议

主键和唯一约束会自动建立索引，另外建议建立：

| 索引字段 | 用途 |
| --- | --- |
| `parking_space(area_id, status, space_code)` | 按区域和编号查找第一个空闲车位 |
| `parking_record(license_plate, entry_time DESC)` | 查询某车牌当前和历史停车记录 |
| `parking_record(status)` | 查询全部在场车辆 |
| `parking_record(entry_time)` | 统计指定日期入场数量 |
| `parking_record(exit_time)` | 统计指定日期离场数量 |
| `payment_record(payment_time)` | 按时间范围统计收入 |
| `payment_record(handled_by)` | 查询管理员办理的收费记录 |

索引数量应根据实际查询决定，不为很少使用的字段盲目建立索引。
