## 2. 成员 2 完成内容

### 2.1 区域 M2-02

- `GET /api/parking-areas?lotId=&status=`：按 `areaCode` 排序，返回 `spaceCount`。

- `PUT /api/parking-areas/{id}`：只改名称/说明；传 `areaCode/lotId` 返回 `4000`。
- `PATCH /api/parking-areas/{id}/status`：停用前锁停车场、查本区域 PARKING 记录。

### 2.2 车位 M2-03

- 归属通过 `parking_area → parking_lot` JOIN 反查，不信任请求体 `lotId`。
- 列表按 `areaCode, spaceCode, id` 排序；`areaId` 与 `lotId` 不匹配返回 `4000`。
- 新增只在启用场/启用区域；同区域编号唯一。
- PUT 仅 FREE 可改；改编号有历史则 `4104`。
- 状态 API 只接受 FREE/DISABLED；OCCUPIED 一律 `4103`。
- 删除仅 FREE 且无历史；启停/删除先锁所属停车场行。
- 前端：`frontend/src/api/space.js`、`ParkingSpacesView.vue`。

### 2.3 本人车辆 M2-04

- 车牌去空白转大写并按省份简称正则校验；空/格式错 `4204`，唯一冲突 `4202`。
- 列表只查本人并按车牌升序；不存在 `4201`，非本人 `4203`。
- 只做启用/停用，不提供删除/换绑；更新 SQL 带 `WHERE id AND owner_user_id`。
- 停用不改变既有停车记录的关联；新入场按临时车处理。

### 2.4 入场 M3

- `POST /api/parking-entries`：请求 `{"lotId":1,"licensePlate":"京A12345"}`。
- 顺序：车牌校验 → ADMIN → 锁启用停车场（成员 1 Guard）→ 全局同牌 `PARKING` → 取生效规则（成员 3）→ 固定排序选 FREE 车位 → 条件占位 → 插入记录。

- 记录保存 lot/space/rule/vehicle/车牌快照/admin/entryTime/status；`recordNo=R+31位UUID`。
- 启用的绑定车辆写 `vehicle_id`；停用/未绑定写 `null`。
- 前端：`frontend/src/api/entry.js`、`ParkingEntriesView.vue`。

## 7. 成员 3 还需要做什么

### 7.1 提供 `FeeRuleQuery.findActiveForLot`

当前 `origin/dev` 没有 `FeeRuleQuery` 或 `FeeRule*`。请成员 3 提供稳定只读方法：

```text
FeeRuleQuery.findActiveForLot(Long lotId)
```

约定：

- 返回该场当前生效规则的最小 DTO（至少含规则 ID）；或直接返回 `Long`。
- 没有生效规则返回 `null`，不要抛 4303；入场服务会统一转 `4303`。
- 只读，不新建/切换规则；不修改 `ParkingEntryMapper.xml`。
- 该方法应能被入场服务在同一事务中调用；不要用独立事务提前提交。

### 7.2 接入适配器

成员 2 已预留 `ParkingEntryDependencyAdapter`。成员 3 合并后，编辑：

```java
private final ParkingLotGuard parkingLotGuard;
private final FeeRuleQuery feeRuleQuery;

public ParkingEntryDependencyAdapter(ParkingLotGuard parkingLotGuard,
                                     FeeRuleQuery feeRuleQuery) {
    this.parkingLotGuard = parkingLotGuard;
    this.feeRuleQuery = feeRuleQuery;
}

@Override
public Long findActiveFeeRuleId(Long lotId) {
    // 按成员 3 实际返回类型取 ID；如果直接返回 Long，直接 return
    FeeRuleView rule = feeRuleQuery.findActiveForLot(lotId);
    return rule == null ? null : rule.getId();
}
```

注意事项：

- `FeeRuleView` 和 `getId` 按成员 3 实际 DTO/字段改名。
- 包名按成员 3 实际位置调整（`service/fee` 或他们定义的包）。
- 不要在 `ParkingEntryService` 里再注入一份 `FeeRuleQuery`；保持一个适配器入口。
- 接入后删除 `FEE_RULE_NOT_READY_MESSAGE` 的抛出，重跑第 3 节测试和第 8 节入场冒烟。

### 7.3 入场记录交接字段

成员 3 的离场/查询按 `parking_record.id` / `record_no` 读取：

```sql
SELECT id, record_no, parking_lot_id, vehicle_id, license_plate,
       parking_space_id, fee_rule_id, entry_admin_id, entry_time, status
FROM parking_record
WHERE id = ?;
```

- `status='PARKING'`，`parking_space.status='OCCUPIED'`。
- `fee_rule_id` 是入场时绑定的规则 ID，离场必须按该 ID 计费，不能取场后来启用的新规则。
- `vehicle_id` 已启用绑定车辆非空；停用/未绑定为 `null`，车牌快照仍保留。
- 成员 3 建自己的 `ParkingExitMapper` / `ParkingRecordQueryMapper`，不改入场 Mapper/XML。
