### 6.2 两个外部方法的预期契约

成员 1：

```text
ParkingLotGuard.lockLot(lotId)
ParkingLotGuard.lockActiveLot(lotId)
```

- `lockActiveLot` 必须在调用方的当前事务内执行 `SELECT ... FOR UPDATE`，不能 `REQUIRES_NEW` 独立提交。
- 停车场不存在抛 `BusinessException(2001)`；已停用抛 `BusinessException(2005)`。
- 方法返回类型按成员 1 实际实现；入场适配器只调用，不使用返回值。

成员 3：

```text
FeeRuleQuery.findActiveForLot(lotId)
```

- 返回规则 ID，或包含规则 ID 的最小 DTO；只读，不新建/切换规则。
- 没有生效规则返回 `null`，入场服务据此抛 `4303`。
- 如果成员 3 返回的是 DTO，适配器必须取“规则 ID”字段，不要取单价/快照字段。

### 6.3 新增适配器

在 `backend/src/main/java/org/example/backend/service/` 新增
`MergedParkingEntryDependency.java`（类名可自定，关键是 `@Primary`）：

```java
package org.example.backend.service;

import org.example.backend.common.ParkingLotGuard;
import org.example.backend.service.fee.FeeRuleQuery;
import org.springframework.context.annotation.Primary;
import org.springframework.stereotype.Component;

@Component
@Primary
public class MergedParkingEntryDependency implements ParkingEntryDependency {

    private final ParkingLotGuard parkingLotGuard;
    private final FeeRuleQuery feeRuleQuery;

    public MergedParkingEntryDependency(ParkingLotGuard parkingLotGuard,
                                        FeeRuleQuery feeRuleQuery) {
        this.parkingLotGuard = parkingLotGuard;
        this.feeRuleQuery = feeRuleQuery;
    }

    @Override
    public void lockActiveLot(Long lotId) {
        parkingLotGuard.lockActiveLot(lotId);
    }

    @Override
    public Long findActiveFeeRuleId(Long lotId) {
        // TODO: 按成员 3 实际返回类型取规则 ID
        // 例：FeeRuleView rule = feeRuleQuery.findActiveForLot(lotId);
        //     return rule == null ? null : rule.getId();
        // 如果成员 3 直接返回 Long，则 return feeRuleQuery.findActiveForLot(lotId);
    }
}
```

操作要点：

- `ParkingLotGuard` 的实际包名按成员 1 落地的 `common/` 调整；`FeeRuleQuery` 的实际包名按成员 3 的 `service/fee/` 或他们定义的包调整。
- `findActiveFeeRuleId` 的 TODO 必须替换成能编译的一行；不知道 DTO 字段时，先看成员 3 的交接说明或 `FeeRuleQuery` 源码，不要猜。
- `@Primary` 会让 Spring 优先选择这个适配器，`PendingParkingEntryDependency` 可以暂时保留；确认后删除占位类或去掉它的 `@Component`，避免以后误用。
- 不要给适配器加 `@Transactional(propagation = REQUIRES_NEW)`。它必须在 `ParkingEntryService.enter` 的同一个事务里执行。
- 不要修改 `ParkingEntryMapper.xml`：锁场/取规则不回到 Mapper，选位/占位/记录插入仍留在入场 Mapper。

### 6.5 交给成员 3 的固定字段

入场成功后，成员 3 按 `parking_record.id` 或 `record_no` 读取：

```sql
SELECT id,
       record_no,
       parking_lot_id,
       vehicle_id,
       license_plate,
       parking_space_id,
       fee_rule_id,
       entry_admin_id,
       entry_time,
       status
FROM parking_record
WHERE id = ?;
```

交接事实：

- `parking_record.status = 'PARKING'`
- `parking_space.status = 'OCCUPIED'`
- `fee_rule_id` 是入场时绑定的规则 ID；离场必须按该 ID 计费，不能取停车场后来启用的新规则。

- 入场响应按 `01` 契约不包含 `vehicleId`；成员 3 需要时直接读上表 `vehicle_id`。
- 成员 3 不修改 `ParkingEntryMapper.xml`，使用自己的 `ParkingExitMapper` / `ParkingRecordQueryMapper`。
