## 4. 表与字段：你实际要写的部分

### 4.1 `parking_area` 停车区域

| 字段 | 你的写法规矩 |
| --- | --- |
| `area_code` | 去空格 + **转大写**，同停车场内唯一（`uk_parking_area_lot_code`）。不同停车场可以都有 `A` |
| `area_name` | 不能空白 |
| `status` | `ACTIVE` / `DISABLED`。`DISABLED` 区域的车位**不参与自动分配** |
| `parking_lot_id` | 由请求指定，必须校验该停车场存在且 `ACTIVE` 才能新增区域 |

### 4.2 `parking_space` 停车位

| 字段 | 你的写法规矩 |
| --- | --- |
| `space_code` | 去空格 + 转大写，**同区域内**唯一（`uk_parking_space_area_code`） |
| `status` | `FREE` / `OCCUPIED` / `DISABLED`，只有这三个值，状态流转见 4.4 |
| `area_id` | 校验区域存在且 `ACTIVE`；页面展示用 `area_code + "-" + space_code`（如 `A-001`） |

### 4.3 `vehicle` 车主车辆

| 字段 | 你的写法规矩 |
| --- | --- |
| `owner_user_id` | **只能从登录上下文取**，绝不能用请求参数传（否则违反 FR-VEHICLE-05 越权） |
| `license_plate` | 去空格 + 转大写；全表唯一（`uk_vehicle_license_plate`），冲突 → "该车牌已被绑定" |
| `status` | 停用是 `DISABLED`，**不物理删除**（FR-VEHICLE-04） |

### 4.4 状态机：你只能走这几条边

```text
车位：FREE --入场--> OCCUPIED --离场(成员3)--> FREE
      FREE --停用--> DISABLED --启用--> FREE
      OCCUPIED --停用--> ✗ 禁止（需求 6.3-5、数据字典 7.4）
区域：ACTIVE --停用--> DISABLED --启用--> ACTIVE
      停用前必须确认该区域内没有 status='PARKING' 的记录（数据字典 6.4）
```

### 4.5 需要跟组长确认的 2 个边界口径（写进 PR 描述，别自己拍板）

1. **车辆停用后的车牌归属**：`uk_vehicle_license_plate` 是全表唯一，车主把车停用（`DISABLED`）后，这个车牌**仍然不能被第二个车主绑定**。数据字典写的是"DISABLED 车辆入场时不自动关联车辆"，但没说能不能被重新绑定。建议按"不能重新绑定，需管理员处理"实现并在 PR 里说明。
2. **停车位要不要物理删除**：需求 FR-SPACE-05 只要求"停用/重新启用"，数据库里还有"有历史记录的车位不能物理删除"。**建议你只做停用、不做删除**，少一个坑且符合 6.3-6；区域则保留删除（FR-AREA-04 明确要求"存在停车位时不能删除"）。

### 5.2 PR 0：`feature/parking-area` 停车区域（约 1.5 天）

**接口**

| 方法 | 路径 | 角色 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/parking-areas?lotId=1&status=` | 管理员 | 按停车场列区域，`lotId` 必填 |
| POST | `/api/parking-areas` | 管理员 | 新增，body: `{lotId, areaCode, areaName, description}` |
| PUT | `/api/parking-areas/{id}` | 管理员 | 改名称/说明（**不允许改 areaCode**，改了会破坏唯一口径） |
| PATCH | `/api/parking-areas/{id}/status` | 管理员 | body: `{"status":"DISABLED"}` |
| DELETE | `/api/parking-areas/{id}` | 管理员 | 区域下有车位则拒绝 |

**校验点（每条都要有对应测试）**

- 同名编号重复：同停车场 `area_code` 重复 → 返回"该停车场已存在区域 A"，**不要直接把数据库唯一冲突抛出去**（先查后插，唯一约束作为兜底）。
- 停用前检查：区域内存在 `status='PARKING'` 的记录就拒绝。
- 删除前检查：`SELECT EXISTS(SELECT 1 FROM parking_space WHERE area_id=?)` 为真就拒绝（外键 `RESTRICT` 是第二道保险）。

**核心 SQL**

```sql
-- 区域列表
SELECT a.id, a.parking_lot_id, a.area_code, a.area_name, a.description, a.status,
       (SELECT COUNT(*) FROM parking_space s WHERE s.area_id = a.id) AS space_count
FROM parking_area a
WHERE a.parking_lot_id = #{lotId}
  AND (#{status} IS NULL OR a.status = #{status})
ORDER BY a.area_code;

-- 停用前校验（返回 true 表示有在场车辆，禁止停用）
SELECT EXISTS (
    SELECT 1 FROM parking_record r
    JOIN parking_space s ON s.id = r.parking_space_id
    WHERE s.area_id = #{areaId} AND r.status = 'PARKING'
);
```

### 5.3 PR 1：`feature/parking-space` 停车位（约 2 天）

**接口**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/parking-spaces?lotId=&areaId=&status=&page=1&size=10` | 列表 + 筛选 + 分页 |
| POST | `/api/parking-spaces` | 新增，body: `{areaId, spaceCode, description}` |
| PUT | `/api/parking-spaces/{id}` | 只允许改 `FREE` 车位的 `spaceCode` / `description` |
| PATCH | `/api/parking-spaces/{id}/status` | `FREE→DISABLED` 或 `DISABLED→FREE`，`OCCUPIED` 一律拒绝 |
| GET | `/api/parking-spaces/available?lotId=1` | 该停车场可用车位（**成员 3 的离场页也可能用到，路径先定死**） |

**核心 SQL：单停车场可用车位**

```sql
SELECT s.id, a.area_code, s.space_code, (a.area_code || '-' || s.space_code) AS full_code
FROM parking_space s
JOIN parking_area a ON a.id = s.area_id
JOIN parking_lot  l ON l.id = a.parking_lot_id
WHERE a.parking_lot_id = #{lotId}
  AND l.status = 'ACTIVE'
  AND a.status = 'ACTIVE'
  AND s.status = 'FREE'
ORDER BY a.area_code, s.space_code;
```

**核心 SQL：停用/启用（用 UPDATE 的条件自己当校验，比先查再改更安全）**

```sql
-- 停用：只有 FREE 能被改
UPDATE parking_space SET status = 'DISABLED', updated_at = CURRENT_TIMESTAMP
WHERE id = #{id} AND status = 'FREE';

-- 启用：只有 DISABLED 能被改
UPDATE parking_space SET status = 'FREE', updated_at = CURRENT_TIMESTAMP
WHERE id = #{id} AND status = 'DISABLED';
```

受影响行数 `0` 时，再查一次当前状态，分别返回"占用中不能停用"/"已停用"/"已是空闲"三种提示。**不要只返回"操作失败"**，答辩现场一定会被问"为什么失败"。

### 5.5 PR 3：`feature/parking-space-allocation` 自动分配（约 1 天）

这一步**只做"查一个可用车位"的能力**，不写记录、不占车位，方便单独测排序规则。分工文档 5.2 要求"按区域编号、车位编号升序分配第一个空闲车位"，需求 Q-05 也是这个口径。

```sql
-- 关键：ORDER BY 用 area_code, space_code（业务编号），不是 id
-- FOR UPDATE 放在 LIMIT 之后，SKIP LOCKED 让并发请求各自拿不同的车位
SELECT s.id, a.area_code, s.space_code
FROM parking_space s
JOIN parking_area a ON a.id = s.area_id
JOIN parking_lot  l ON l.id = a.parking_lot_id
WHERE a.parking_lot_id = #{lotId}
  AND l.status = 'ACTIVE'
  AND a.status = 'ACTIVE'
  AND s.status = 'FREE'
ORDER BY a.area_code, s.space_code
LIMIT 1
FOR UPDATE OF s SKIP LOCKED;
```

**要注意的两个细节**

- `space_code` 是字符串，演示数据里是 `001`～`010`（`LPAD` 补零），所以字符串升序 = 数字升序。但如果你自己新增车位时写 `1`、`2`、`10`，字符串排序会变成 `1, 10, 2`。**要么统一按 3 位补零，要么在 SQL 里 `ORDER BY LENGTH(space_code), space_code`**，二选一并在 PR 里写明。
- 这条 SQL 一定要加 `JOIN parking_lot` 并判断 `l.status='ACTIVE'`：需求 8.1 明确"停用停车场不能办理新的车辆入场"，只查车位状态会漏掉这个条件。

### 5.6 PR 4：`feature/vehicle-entry` 车辆入场（约 2.5 天，核心）

**执行顺序（必须按这个顺序，每一步失败都要给出可读原因）**

| 步骤 | 做什么 | 失败时返回 |
| --- | --- | --- |
| 1 | 车牌规范化：`replaceAll("\\s+","")` + `toUpperCase(Locale.ROOT)` | 4001 车牌格式不正确 |
| 2 | 正则校验 `^[\u4e00-\u9fa5][A-Z][A-Z0-9]{5,6}$` | 4001 |
| 3 | 查该车牌是否已有 `status='PARKING'` 记录 | 4002 该车牌已在场 |
| 4 | 查停车场存在且 `ACTIVE` | 4004 停车场不存在或已停用 |
| 5 | 取该停车场 `is_active=true` 的 `fee_rule.id` | 4005 未配置生效收费规则 |
| 6 | 分配车位：手动 `spaceId` 校验归属+`FREE`；否则走 5.5 的 SQL | 4006 车位不属于该停车场 / 4003 停车场已满 |
| 7 | 按车牌查 `status='ACTIVE'` 的 `vehicle`，有则关联，无则 `vehicleId = null` | — |
| 8 | 插入 `parking_record`（`record_no` 生成） | 4091 并发重复入场 |
| 9 | `UPDATE parking_space SET status='OCCUPIED' WHERE id=? AND status='FREE'`，受影响 0 → 抛异常回滚 | 4007 车位已被占用 |
| 10 | 返回结果 | — |

**事务与并发：这是你答辩最值钱的一段**

```java
@Service
public class ParkingEntryService {

    @Transactional(rollbackFor = Exception.class)   // 步骤 3~9 同一个事务
    public EntryResult enter(EntryRequest req) {
        String plate = PlateNormalizer.normalize(req.getLicensePlate());   // 步骤 1
        if (!PlateNormalizer.isValid(plate)) throw new BusinessException("4001", "车牌格式不正确");

        // 步骤 3：已入场校验
        if (parkingRecordMapper.existsParkingByPlate(plate)) {
            throw new BusinessException("4002", "该车牌已在场，请先办理离场");
        }
        // 步骤 4：停车场状态
        ParkingLot lot = parkingLotMapper.findActiveById(req.getLotId());
        if (lot == null) throw new BusinessException("4004", "停车场不存在或已停用");
        // 步骤 5：生效收费规则（成员 3 的表，只读）
        Long feeRuleId = feeRuleMapper.findActiveIdByLotId(lot.getId());
        if (feeRuleId == null) throw new BusinessException("4005", "该停车场未配置生效收费规则");
        // 步骤 6：分配车位（手动 or 自动，自动那条 SQL 带 FOR UPDATE SKIP LOCKED）
        ParkingSpace space = resolveSpace(lot.getId(), req.getSpaceId());
        // 步骤 7：已绑定车辆关联
        Long vehicleId = vehicleMapper.findActiveIdByPlate(plate);   // 可能为 null，临时车辆
        // 步骤 8：插入记录
        ParkingRecord record = new ParkingRecord();
        record.setRecordNo(RecordNoGenerator.next());
        record.setParkingLotId(lot.getId());
        record.setVehicleId(vehicleId);          // 临时车辆为 null
        record.setLicensePlate(plate);           // 快照，永远存
        record.setParkingSpaceId(space.getId());
        record.setFeeRuleId(feeRuleId);
        record.setEntryAdminId(CurrentUserSupport.currentAdminId());
        record.setStatus("PARKING");
        parkingRecordMapper.insert(record);      // entry_time 交给数据库默认值
        // 步骤 9：占位（条件更新，受影响行数 0 说明被别人抢先）
        if (parkingSpaceMapper.occupy(space.getId()) != 1) {
            throw new BusinessException("4007", "车位已被占用，请重新分配");
        }
        return EntryResult.of(record, lot, space);
    }
}
```

三个必须讲清楚的保证：

1. **一致性**：第 8 步和第 9 步在同一事务。任一步异常 → `parking_record` 不落库、车位仍是 `FREE`。这正是验收标准 12.1-8 那条"不产生车位已释放但记录未完成"的反面情况。
2. **并发**：`FOR UPDATE SKIP LOCKED` 让两个同时进场的请求拿不到同一个车位；即使绕过加锁，`uk_parking_record_active_space` 和 `uk_parking_record_active_plate` 两个部分唯一索引也会让第二个事务失败回滚。**数据库约束是最后防线，不是唯一手段，两者都要有**。
3. **`catch` 数据的唯一约束冲突要分类处理**：`DuplicateKeyException` 里判断约束名，`..._active_plate` → 4002，`..._active_space` → 4007，其他 → 抛出去。

**`record_no` 生成**（数据字典 9.3 规定格式 `PR + yyyyMMddHHmmss + 4 位随机`）：

```java
public static String next() {
    String ts = LocalDateTime.now().format(DateTimeFormatter.ofPattern("yyyyMMddHHmmss"));
    String rnd = randomAlphanumeric(4);   // 大写字母+数字，SecureRandom 或 ThreadLocalRandom
    return "PR" + ts + rnd;               // 长度 20，VARCHAR(32) 够用
}
```

**可靠性验证手段（做一次就够，但一定要做）**：把 `fee_rule_id` 故意传成不存在的 id 让外键失败，然后查 `parking_space.status` 仍是 `FREE`、`parking_record` 没有新行。这就是"事务回滚"的现场证据，答辩直接演示这个。

## 11. 常见坑速查

| 坑 | 表现 | 正确做法 |
